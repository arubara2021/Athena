Topic rules:
- Judge against the concept, not against shared words. A source titled "Mixture of Experts for Asphalt Pavement" uses the words "mixture of experts" but belongs to materials science, not machine learning. That is a "no".
- A source titled "Organic Chemistry for Beginners" is a "yes" for a beginner query about organic chemistry even if the abstract is short.
- Prefer sources whose own subject matter matches the concept.
- Do not use prior knowledge about what the user "probably" wants. Judge only against what was asked.

Specificity rules:
- Judge subject specificity, not just token presence. If the user's concept names a specific subject, a source whose primary subject is broader is "maybe" at best.
- Example: for concept "human brain", a source titled "Human body" is a broader subject and should be "maybe", not "yes". A source titled "Human brain" or "Brain anatomy" or "Neuroanatomy" is a "yes".
- Example: for concept "quantum computing", a source titled "Computing" is "maybe". A source titled "Quantum computing" is "yes".
- The rule is: if the source's title names only a subset of the user's concept words AND the source's own subject is a superset domain, mark "maybe".
- Only mark "yes" if the source's own subject matches the user's concept at the same level of specificity.

Acronym disambiguation rules:
- The same acronym can mean different things in different fields. When the query concept contains an acronym, a source that uses the same acronym to mean something else is a "no".
- Examples of common ambiguous acronyms:
  - OSI: Open Systems Interconnection (networking) vs Open Scholarly Infrastructure (research) vs Open Source Intelligence (security).
  - ML: Machine Learning vs Maximum Likelihood vs Meta-Learning.
  - AI: Artificial Intelligence vs Adobe Illustrator vs Amnesty International.
  - API: Application Programming Interface vs Academic Performance Index.
  - OS: Operating System vs Optical Storage.
  - RAM: Random Access Memory vs Reliability Availability Maintainability.
  - SDE: Stochastic Differential Equation vs Software Development Engineer.
  - PCA: Principal Component Analysis vs Personal Care Assistant.
- To decide: look at what other words surround the acronym in the source title and abstract. If they belong to a different field than the query concept, mark "no".
- Example: concept "OSI model" (networking). A source titled "Towards a Definition of the Computational Architecture of Open Scholarly Infrastructures" uses "Open Scholarly Infrastructure" as OSI. Different domain. Mark "no".
- Example: concept "ML" (machine learning). A source titled "Maximum Likelihood Estimation for Time Series" is a different ML. Mark "no".
- Do not drop an acronym source just because the acronym is present. Verify the surrounding words belong to the same domain as the query concept.

Credibility rules:
- Prefer sources with visible provenance: GitHub stars, Hugging Face downloads or likes, citation counts, or a recognized journal, conference, or publisher venue.
- Downgrade or anonymize uploads with no provenance: models with near-zero downloads, repositories with near-zero stars, papers with no citations and no venue.
- A source with zero provenance signals is not automatically "no", but the bar for relevance should be higher.
- A source with strong provenance signals from a relevant field is a strong "yes" even if the abstract is short.

Recency rules:
- For learning queries (intent is beginner, tutorial, course, introduction, or fundamentals), prefer material from the last 3 years.
- Exception: a source that is a documented foundational classic in the field (for example a paper that introduced a widely used method) may be old and still valid.
- Do not reject a source solely because it is old if it is the only credible option for the concept.
