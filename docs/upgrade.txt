SECTION 1: CURRENT STATE vs TARGET STATE
====================================================================================================

CURRENT STATE (Pipeline Agent):
--------------------------------
- Linear pipeline: Input -> Process -> Output
- Fixed stages executed in order
- No self-correction
- No dynamic planning
- No memory between runs
- No tool discovery
- One pass, no iteration

TARGET STATE (Autonomous Agent):
--------------------------------
- Dynamic loop: Plan -> Act -> Observe -> Reflect -> Repeat
- Agent decides what to do next
- Self-corrects when results are poor
- Dynamically plans based on goal
- Remembers past research
- Discovers and uses tools
- Multiple passes until goal is satisfied

COMPARISON TABLE:
+---------------------------+-------------------+-------------------+
| Feature                   | Current (v1.0)    | Target (v2.0)     |
+---------------------------+-------------------+-------------------+
| Execution Model           | Linear Pipeline   | Agentic Loop      |
| Planning                  | Hardcoded Steps   | Dynamic Planning  |
| Error Recovery            | Fallback Only     | Self-Correction   |
| Memory                    | None              | Persistent        |
| Tool Use                  | Fixed 7 Clients   | Dynamic Tools     |
| Iteration                 | Single Pass       | Multi-Pass        |
| Token Awareness           | None              | Budget Tracking   |
| Goal Decomposition        | None              | Automatic         |
| Quality Assessment        | None              | Self-Evaluation   |
+---------------------------+-------------------+-------------------+

SECTION 3: PHASE 1 — TOKEN CONTROL SYSTEM
====================================================================================================

PURPOSE:
--------
Control and track token usage across all LLM calls to ensure the agent
stays within free-tier limits. This is the FOUNDATION of the autonomous
upgrade. Without this, the agent will burn through free tokens in minutes.

ARCHITECTURE DIAGRAM:
=====================

    +================================================+
    |            TOKEN BUDGET MANAGER                 |
    |================================================|
    |                                                |
    |  +------------------------------------------+  |
    |  |         BUDGET CONFIGURATION              |  |
    |  |                                          |  |
    |  |  Total Budget Per Task:  40,000 tokens   |  |
    |  |  Warning Threshold:      30,000 tokens   |  |
    |  |  Critical Threshold:      5,000 tokens   |  |
    |  |  Wrap-Up Threshold:       3,000 tokens   |  |
    |  +------------------------------------------+  |
    |                                                |
    |  +------------------------------------------+  |
    |  |         TOKEN LEDGER                      |  |
    |  |                                          |  |
    |  |  Task ID: abc-123                        |  |
    |  |  Started: 2026-09-02 16:00:00           |  |
    |  |                                          |  |
    |  |  Category          | Spent   | Limit     |  |
    |  |  ------------------+---------+---------  |  |
    |  |  Planning          | 2,000   | 5,000    |  |
    |  |  Search Queries    | 1,500   | 3,000    |  |
    |  |  Source Reading    | 8,000   | 15,000   |  |
    |  |  Ranking           | 6,000   | 8,000    |  |
    |  |  Summarization     | 4,500   | 6,000    |  |
    |  |  Reflection        | 1,200   | 3,000    |  |
    |  |  ------------------+---------+---------  |  |
    |  |  TOTAL             | 23,200  | 40,000   |  |
    |  +------------------------------------------+  |
    |                                                |
    |  +------------------------------------------+  |
    |  |         COST TRACKER                      |  |
    |  |                                          |  |
    |  |  Tracks tokens per LLM call              |  |
    |  |  Deducts from budget automatically       |  |
    |  |  Raises BudgetWarning at threshold       |  |
    |  |  Forces WrapUpMode when critical         |  |
    |  +------------------------------------------+  |
    |                                                |
    +================================================+


MODEL TIER SELECTION (Token-Efficient):
=======================================

    +----------------------------------------------------------+
    | DECISION: Which model to use for which task?             |
    +----------------------------------------------------------+
    |                                                          |
    |  TASK TYPE          | MODEL TIER    | TOKEN COST        |
    |  -------------------+---------------+------------------ |
    |  Simple decisions   | FAST (cheap)  | ~100-500 tokens   |
    |  Query expansion    | FAST          | ~200-500 tokens   |
    |  Summarization      | FAST          | ~300-800 tokens   |
    |  Tool selection     | FAST          | ~100-300 tokens   |
    |  Reflection         | FAST          | ~200-500 tokens   |
    |  Deep analysis      | STRONG        | ~1000-3000 tokens |
    |  Final ranking      | STRONG        | ~2000-5000 tokens |
    |  Learning path      | STRONG        | ~1500-3000 tokens |
    |  Final synthesis    | STRONG        | ~2000-4000 tokens |
    |                                                          |
    +----------------------------------------------------------+

    RULE: Use FAST model for 80% of calls, STRONG for 20%
    This keeps token usage LOW while maintaining quality

    agent/token_ledger.py       - Per-call token recording
    agent/cost_tracker.py       - Aggregation and reporting

====================================================================================================

PURPOSE:
--------
Replace the linear pipeline with a dynamic loop that allows the agent

    |           AGENTIC LOOP ENGINE                   |
    |================================================|

    |  |    {task: "Build path", done: false},    |  |
    |  |  ]                                       |  |
    |  +------------------------------------------+  |
    |                                                |
    |  LOOP ITERATION:                               |
    |                                                |
    |  1. THINK                                      |
    |     - What is the next best action?            |

    |     - What information do I need?              |
    |     - Use FAST model (~200 tokens)             |

    |     - Execute the selected tool                |

=====================

    +================================================+
    |            PLANNER MODULE                       |

    |                                                |

    |    - What does the user want?                  |
    |    - What level? (beginner/advanced)           |
    |    - What format? (learning path/report)       |
    |                                                |
    |  Step 2: DECOMPOSE                             |
    |    - Break into sub-tasks                      |
    |    - Order by dependency                       |
    |    - Estimate token cost per sub-task          |
    |                                                |
    |  Step 3: ALLOCATE BUDGET                       |
    |    - Distribute token budget                   |
    |    - Prioritize critical sub-tasks             |
    |    - Reserve budget for reflection             |
    |                                                |
    |  OUTPUT: Execution Plan                        |
    |                                                |
    |  Example Plan:                                 |
    |  +------------------------------------------+  |
    |  | Sub-task 1: Search basics     | 5000 tk |  |
    |  | Sub-task 2: Read top sources  | 8000 tk |  |

    |  | Sub-task 4: Build path        | 5000 tk |  |
    |  | Sub-task 5: Summarize         | 4000 tk |  |
    |  | Sub-task 6: Reflect & fix     | 3000 tk |  |
    |  | Reserve: Final synthesis      | 5000 tk |  |
    |  | ---------------------------------------- |  |
    |  | TOTAL                         | 36000 tk|  |
    |  +------------------------------------------+  |
